# Make Douyin Great Again 回归测试

## 选用例

日常改动和发布前默认做增量测试。从[脚本用例](tests/script/README.md)和[文本用例](tests/text/README.md)挑选以下检查，重复项合并执行。

- **冒烟**跑受影响功能最短的用户流程。扩展源码或打包有改动时，核对文件入口和脚本语法。
- **迭代必测**覆盖 `SHARE-01` 真实分享复制和 `DOUBAO-01` 豆包草稿。已有同一迭代的实测结果且后续改动未影响该行为时，可以复用。
- **变更点**验证本次改动的预期及相关边界。播放器共用逻辑变更时，重点检查详情、推荐和精选弹层里的作品是否匹配。

用户指定范围时按该范围执行。项目全量回归只在用户明确要求时执行。仅改文档时核对规则、用例编号和路径。

## 判定与执行

先根据本次需求定义正确结果，以已确认的行为和当次页面数据作对照。分享短链核对落地作品，下载文件和豆包草稿核对点击时播放器中的作品。

- **脚本**按编号执行固定检查，例如清单引用的资源是否齐全。
- **AI**按文本步骤检查真实交互，符合预期即记通过。重要流程变更或反复报告的故障，走一遍实际操作。
- **用户**在需要授权或仍有预期分歧时作决定。AI 先给出已经验证的证据和待确认项。

修 bug 时用同一检查对照修前和修后。脚本出错时，AI 在同一样本查找第一处差异，保留首次失败和复现条件，重跑受影响用例。原样本或等价样本覆盖原触发条件并通过后，才记为修复已验证。

### 环境与操作

获准实测时，优先复用已连接的 Chrome `my-chrome` 和现有登录状态。从仓库加载的版本使用 `extension/`。验证工作区代码时确认扩展来源和版本，重载扩展并刷新受测标签页。先检查已有会话和扩展状态。需要用户切换账号、重连或调整已启用扩展才能隔离结果时，把受影响用例记为待验证。

从[样本入口](references/samples.md)找作品，记录当次 URL 或作品 ID。共享标签页、剪贴板或扩展设置的检查串行执行。豆包流程验收到草稿为止。真实提交「不感兴趣」只在用户明确授权的作品上执行，随后验证原生撤销。测试涉及首屏或滚动性能时，在相同浏览器、入口和操作下对照前后结果。

## 结果与清理

- 按编号记录样本、扩展版本和实际结果，标明通过、失败或未验证。缺少登录、授权或合适样本时，写明具体缺少的条件，继续可执行的用例。分别记录脚本和 AI 实测的证据。
- 完成、失败或中断时，恢复本次改动的扩展设置，关闭本次打开的测试标签页，回到原标签页。将本次的一次性下载、截图和日志移入系统废纸篓。
- 为测试启动本地服务或后台进程时记录任务或进程 ID，结束时停止并确认退出。测试前已运行、由本次复用的服务继续运行。

## 维护

- `tests/script/` 按功能放自动化脚本，按任务选语言。每个检查独立判定，索引和输出使用同一编号。有测试函数时用 `test_PKG_01` 这样的名称。
- `tests/text/` 每类功能一个 Markdown 文件，README 只列索引。每条用例有唯一编号、前提、步骤和预期。切换执行方式时保留原编号。
- 用户明确要求发布时，将本版已实测通过的新行为加入用例库。已有行为更新原条目，补上可复用的样本和曾漏测的触发条件。
