# Make Douyin Great Again 回归测试

## 测试前

日常改动和发布前默认做增量测试。从[脚本用例](tests/script/README.md)和[文本用例](tests/text/README.md)挑选以下检查，重复项合并执行。

- **冒烟**跑受影响功能最短的用户流程。扩展源码或打包有改动时，核对文件入口和脚本语法。
- **迭代必测**覆盖 `SHARE-01` 真实分享复制和 `DOUBAO-01` 豆包草稿。已有同一迭代的实测结果且后续改动未影响该行为时，可以复用。
- **变更点**验证本次改动的预期及相关边界。播放器共用逻辑变更时，重点检查详情、推荐和精选弹层里的作品是否匹配。

用户指定范围时按该范围执行。项目全量回归只在用户明确要求时执行。仅改文档时核对规则、用例编号和路径。

先根据本次需求定义正确结果，以已确认的行为和当次页面数据作对照。分享短链核对落地作品，下载文件和豆包草稿核对点击时播放器中的作品。

获准实测时，从[样本入口](references/samples.md)找作品，记录当次 URL 或作品 ID。优先复用已连接的 Chrome `my-chrome` 和现有登录状态。验证工作区代码时，先核对会话和已启用扩展，再从 `extension/` 重载本地版并刷新受测标签页。确认测试使用的扩展来源和版本。需用户切换账号、重连或调整扩展才能隔离结果时，受影响用例记为未验证。

`tests/script/` 和 `tests/text/` 各按功能分文件，README 放索引。索引、脚本输出和文本用例共用稳定编号，测试函数用 `test_PKG_01` 这样的名称。文本用例写清前提、步骤和预期。

## 测试时

- **脚本层**按编号做固定检查，例如核对清单引用的资源。
- **AI 层**按文本步骤实测。重要流程变更或故障反复出现时，走一遍实际操作。脚本异常时保留首次失败，在同一样本查找第一处差异。修前修后用同一检查，重跑受影响的用例，覆盖原触发条件后再确认修复。
- **人类层**处理授权或预期取舍。AI 先报告已验证的证据和待确认项。

共享标签页、剪贴板或扩展设置的检查串行执行。豆包流程验收到草稿为止。真实提交「不感兴趣」只在用户明确授权的作品上执行，随后验证原生撤销。首屏或滚动性能在相同浏览器、入口和操作下对照前后结果。条件不足时，继续执行独立用例。

## 测试后

- **结果**按编号记录样本、扩展版本和实际结果，标明通过、失败或未验证。写明缺少的前提，分别记录脚本和 AI 的证据。
- **清理**在完成、失败或中断时恢复本轮改动的扩展设置，关闭测试标签页并回到原标签页。把一次性下载、截图和日志移入系统废纸篓。记录本轮启动的服务或进程 ID，结束时停止并确认退出，保留原有服务。
- **维护**在用户明确要求发布时，把本版已验证的新行为、可复用样本和曾漏测的触发条件纳入用例库。已有行为或执行方式变更时沿用原编号。
